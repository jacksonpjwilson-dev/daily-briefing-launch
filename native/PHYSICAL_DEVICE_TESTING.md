# Signed physical-device testing

P0 changes harden the existing local app. Unsigned simulator builds cannot validate provisioning, App Groups, WeatherKit, locked-device Keychain behavior, paired Watch transfer or actual background opportunities. Use a development branch and keep PR #1 draft until these checks are recorded.

## 1. Prepare identities and signing

1. Use a Mac with Xcode 16 or later, an Apple development team, and a physical iPhone running iOS 17 or later. Enable Developer Mode on the phone, connect/trust it, and add the Apple account in Xcode → Settings → Accounts. Use a paired watchOS 10+ Watch for companion tests. WeatherKit and distribution require appropriate developer-program access.
2. Back up any existing on-device data before an upgrade test. Keep CloudKit off initially. Do not delete the installed app when testing migration; install the hardened build over the earlier build using the same signed identifiers.
3. Replace `com.example.DailyBriefing` with the team's chosen base identifier consistently in `native/generate_project.py`, Swift sources, and `native/ci_simulator_smoke.py`. The four IDs are the base, `.widgets`, `.watchkitapp`, and `.watchkitapp.widgets`. Preserve the Watch companion relationship. Replace `group.com.example.DailyBriefing` everywhere, and the background-task ID `<base>.refresh` in both source and generated Info.plist. Reserve a matching iCloud identifier only when testing that optional feature. Search for `example` across `native/` to catch escaped identifier patterns as well as plain strings; the smoke check must match the identifier it launches.
4. Run `python3 native/generate_project.py` and `python3 native/validate_project.py`. Open `native/DailyBriefing.xcodeproj`; select the same team and automatic signing for all four targets. Register/enable the same App Group on every applicable identifier and provision each target. iPhone and Watch containers are separate; WatchConnectivity moves the sanitized snapshot between them.
5. For real weather, enable WeatherKit for the iPhone App ID, add `com.apple.developer.weatherkit = true` to the app entitlement generated by `generate_project.py`, and set its `WeatherKitConfigured=True`. Regenerate and reprovision. Do not blindly select `OptionalCloudWeather.entitlements`: that template also enables CloudKit. The generator rewrites plists and entitlements, so make durable capability changes in the generator.
6. Keep iCloud/CloudKit disabled until the actual signed container, local-store transition and two-device behavior are tested. APNs, server credentials and new providers are outside P0. No push entitlement is needed for the existing local reminders. Existing `fetch`/`audio` background modes and Live Activity support are already generated; enable Background App Refresh in device Settings.
7. Select the DailyBriefing scheme and the connected iPhone, then Build and Run. Optional command-line equivalent after replacing the values:

   ```sh
   xcodebuild -project native/DailyBriefing.xcodeproj -scheme DailyBriefing \
     -configuration Debug -destination 'platform=iOS,id=YOUR_DEVICE_UDID' \
     DEVELOPMENT_TEAM=YOUR_TEAM_ID -allowProvisioningUpdates build
   ```

   Use the actual generated entitlement file; do not use `CODE_SIGNING_ALLOWED=NO` for this test. Install/add the signed widgets and Watch companion separately as needed.

## 2. Exercise the local daily workflow

Record build SHA, OS/device, permissions, source setup, expected/actual results, screenshots and device logs. Tests involving real account data should use a small dedicated calendar/reminder list and consented AI endpoint.

| Check | Required result |
| --- | --- |
| Fresh install; deny then grant calendar, reminders, location and notifications | No unsolicited access prompts/provider uploads; unconfigured and denied states differ; explicit permission actions and resume recover. Select the contributing and work calendars after authorization. |
| Manual 22:00–06:00 shift across midnight | Shift remains visible at 00:30; same-start-day calendar shift stays overridden, including a shortened manual override. Test manual-only mode without calendar access. |
| 00:15 shift, 45-minute lead, refresh at 23:30 | Target date is tomorrow; its appointments/forecast are used. Before the lead window, target remains today. Check DST changes, travel/time-zone changes and days-off rules. |
| Move an existing appointment; change end, location or link | Change is reported with stable event identity; pin survives. Unchanged read content stays read; a meaningful revision becomes unread. Include recurring/detached events and calendar deletion. |
| Disable a section or AI consent during an in-flight request | Pending work is canceled, disabled providers are not invoked on later refreshes, and old data disappears from Today, filtered History/search/share, speech and newly rendered widgets/Watch snapshots. Changing AI endpoint resets consent and cannot reuse another origin/service's token. |
| Airplane mode, slow/unresponsive source, service failure | Deadlines finish promptly with honest cached/as-of labels; successful sections remain saved. METAR and TAF fail independently and expired reports are labeled/excluded from summary inputs. |
| Interrupt/expire a background refresh after one source completes | Same history row contains the checkpoint after relaunch and is marked interrupted; next refresh can complete. Inspect background resubmission. Force-quit is a recovery test, not a promise iOS will relaunch the app. Use Xcode's simulated background launch/expiration tools as supplemental checks. |
| Lock phone with a configured AI/monitoring token | Unavailable Keychain credentials prevent the authenticated stage from uploading; unlock and retry recover. Test token replacement/deletion and 401/403/429/redirect handling against the actual service. |
| Upgrade earlier local store/settings | Existing briefings, shifts, pins and settings survive. Legacy payload originals are retained. Use an isolated test copy for corrupt/future-version cases: recovery notice, blocked autosave, last-good restore and explicit keep-current must preserve originals. Never corrupt a user's only store. |
| Notifications disabled/denied, quiet hours, changed shift | No duplicates or unrelated pending notifications removed; local reminder tap opens Today. Replacements succeed before obsolete requests are removed. Record observed delivery, separately from calculated target time. |
| Signed App Group, widgets and paired Watch | Snapshot is readable on each signed target; cached/fresh timestamps agree, deep links work, disable/revoke updates propagate after connectivity resumes. Test reconnection, lock screens and OS privacy settings. |
| Live Activity, Siri, speech and accessibility | Start/end shift countdown, revoke/disable schedule, test stale/expiry while suspended; invoke each Shortcut; test audio interruptions and voice/rate; check VoiceOver, large Dynamic Type, contrast and reduced motion. Section-aware speech advancement remains follow-up work. |

## 3. Understand the remaining gates

- iOS controls background opportunities, notifications and widget rendering. An already-rendered OS widget image or disconnected Watch cannot be recalled instantly; the privacy gate protects subsequent controllable reads/transfers. Verify actual rendering and reconnection behavior on devices before making stronger claims.
- The local app schedules reminders, not guaranteed pre-generated remote briefings. Remote enrollment, scheduling/storage/APNs and native ingestion remain P1. Email and sports remain explicit disconnected boundaries; AI/monitoring need compatible configured services. No mock data makes those integrations operational.
- WeatherKit, local notification replacement, Keychain and Watch behavior need the signed tests above even with green core tests. CloudKit needs a separate backed-up, two-device migration/account-change campaign before enabling it for users.
- After development tests pass, supply production icons, review privacy/retention/source branding, create a signed Release archive and test an install/update through TestFlight. Record and resolve release-blocking failures before taking PR #1 out of draft.
